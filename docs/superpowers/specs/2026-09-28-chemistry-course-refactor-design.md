# Дизайн-спека: единый каркас интерактивного курса химии

Дата: 2026-09-28
Статус: на ревью
Автор: Глеб (химик/преподаватель/кодер) + ассистент

---

## 0. Контекст и цель

Есть авторский курс интерактивной химии: автономные HTML-файлы, которые ученик
открывает на телефоне из Telegram или встраивает в доску tldraw через `iframe`.
Контент генерируется ИИ-агентом, автор проверяет глазами.

Проблема сейчас:

- нет чёткой единой структуры уроков — блоки «скачут»;
- стиль местами расходится;
- симуляции — черновики, без единого стандарта и без масштабирования под телефон;
- тестовый движок продублирован 5 раз;
- данные размазаны (`module.json` + `manifest.json` + хардкод в JS);
- нет машинного описания курса и компонентов, поэтому агент вынужден догадываться;
- разборчивость исходников падает с ростом числа модулей.

**Цель этой работы:** заложить единый каркас «данные → канон → билдер → линт → движки»,
привести Модуль 1 к этому каркасу как эталон и дальше тиражировать на все 14 модулей.

**Не цель прямо сейчас:** полный рефакторинг всех 14 модулей, сайт/роутер, личный
кабинет, монетизация, аналитика, медиа.

### Критерии успеха

1. Есть машинные источники правды: `course.json`, `components.json`, `glossary.json`,
   `elements.json`, `sims.json`, `messages.json`, единый `module.json`.
2. Модуль 1 полностью собран из `src/` по новому каркасу и открывается на телефоне.
3. Один тестовый движок `quiz.js` обслуживает все типы тестов (3 типа вопросов).
4. `lint.py` ловит неканонический контент и падает с ERROR до «готово».
5. `build.py` собирает модуль, отчёт и (по флагу) шлёт файл в Telegram.
6. Ни один урок не содержит инлайн-стилей; все блоки — из реестра.
7. Пилот проверен на вертикальном телефоне самим автором.

## 1. Принятые решения (decision log)

### 1.1. Мир и аудитория
- Ученики: 7–9 класс (сейчас 3), максимум ~10; в перспективе научпоп для любого возраста.
- Устройства любые, **главный — вертикальный телефон** (390×844 ориентир).
- Автор — единственный исполнитель (контент + код), 1–2 ч/день, соло.
- Жёстких «нет» нет; дедлайн мягкий (≈ Новый год), версионирование через GitHub.

### 1.2. Доставка
- 1 файл на модуль (`dist/module_1.html`) → Telegram; iFrame в tldraw.
- Офлайн обязателен → всё инлайнится, ноль внешних зависимостей.
- Бот пока только авторский: присылает собранный файл и отчёт.
- Ученик идёт: урок 1 → домашка → урок 2 → …; порядок не блокируется.
- Результат: «прошёл/не прошёл», подтверждение скриншотом; кабинета/прогресса нет.
- Медиа (фото/гиф/шортсы) — позже, внешними ссылками со заглушкой.

### 1.3. Методика
- Каждый урок содержит все канонические блоки; 3–5 уроков на модуль.
- 15–20 мин — рекомендация, не жёсткий лимит.
- Каждый урок привязан к реальной жизненной задаче (отдельный блок).
- Домашка — рукописная в тетради, проверяет автор; есть памятка по оформлению.
- Тесты — самопроверка: **порог 80% везде** (включая безопасность), без полбалла и
  второй попытки, неограниченные повторы, без блокировки контента и анти-клика.
- Входной тест и разогрев — в каждом модуле. Повторение прошлого — только входным.
- Тон нейтральный («давай разберёмся»), примеры в два слоя; Фейнман — единственный
  приём «учиться учиться» сейчас. Джонстон — строго с Модуля 4б.
- Эмодзи остаются; 4 цвета коллаутов остаются; достижений/прогресс-баров нет.

### 1.4. Дизайн
- Палитра, шрифт (`Inter/системный`), светлый фон — как есть.
- Тёмной темы, печати, брендинга — нет.
- Инлайн-стили в контенте запрещены; только канонические классы.
- Тап-зоны ≥44px; hover всегда дублируется тапом.
- Широкая графика — горизонтальный скролл + подсказка «разверни телефон».
- Sticky-оглавление модуля есть; prev/next навигация убирается.
- Лоадер/скелетон для тяжёлых симов — есть.
- Витрина компонентов (`dist/styleguide.html`) — есть.

### 1.5. Интерактив и симуляции
- Обёртка сима v2 (`makeSim`), режимы `watch/tune/sandbox`, «один сим — одно явление»,
  строка «честно/условно», нулевое состояние, микровопрос — канон.
- Транспорт — только где есть динамика; `sandbox` — конструкторы молекул.
- Дроп-игры 2–4 корзины; `scenario` — да; таксономия 8 типов закрыта.
- Симы конфигурируемы данными и тестируются; ядро `ChemDraw` над `elements.json`.
- Сквозной LOD-переключатель «уровень глаз ↔ уровень частиц».
- DPR-масштаб и пауза rAF вне экрана — обязательны.
- Частиц до тысяч; размер файла до нескольких мегабайт — приемлемо.

### 1.6. Тесты
- Один `quiz.js`; данные — JSON-островок `<script type="application/json">`.
- Конфиги: `warmup`, `entry`, `practice`, `final`, `safety`; все порог 80%.
- Перемешивание вопросов и вариантов; итоговый — выборка из банка.
- 3 типа вопросов: один правильный, несколько правильных, сопоставление.
- `why` обязателен; счёт только в конце; есть разбор ошибок.
- Тексты результатов — общий банк `messages.json` (случайный выбор по ситуации).
- Валидация вопросов — ERROR линтера (не аварийное падение сборки).

### 1.7. Данные и процесс
- Markdown — **черновик автора для агента**, билдер его не парсит.
- Канон HTML собирает агент по реестру + DESIGN + SIMULATIONS.
- Раскладка урока: `lesson.md` + `body.html` + `answers.md`.
- Папки `module_1`, `module_2`, … (сквозная нумерация; 3а/3б исчезнут).
- `course.json` — структура курса; автоподсветка терминов из `glossary.json`.
- CSS/JS подбираются билдером автоматически по блокам.
- Билдер пишет `dist` даже при FAIL, помечает, шлёт отчёт, возвращает ненулевой код.
- `dist/` коммитится; бэкап — GitHub; одна ветка; CI нет.
- Агент делает модуль целиком, автор проверяет собранный файл, потом точечные правки.
- `BACKLOG.md` версионируется.
- Скиллы: глобальные opencode + спец-скилл по химическим урокам.

### 1.8. Осознанно «не чиним» сейчас
Пакет билдера, Jest/Pytest/ESLint, headless-браузер и скриншоты, большой рефактор
движка «взрывом», `legacy/`, внешние библиотеки, Markdown-парсер, брендинг,
прогресс, аналитика, тёмная тема, печать, lazy-load, идентификация.

## 2. Целевая архитектура

```
course.json                      # уровни A–F, модули: темы/навыки/пререк/статус/иконка
BACKLOG.md                       # версионируемый бэклог
DESIGN.md / SIMULATIONS.md / PROGRAM.md / STRUCTURE.md / SOURCES.md
docs/superpowers/specs|plans/    # спеки и планы
src/
  build.py                       # сборка + подкоманды `new`, `--send`
  lint.py                        # проверки ERROR/WARN
  shared/
    shell.html                   # вынесенный HTML-шаблон оболочки
    css/{core.css, module_*.css}
    js/{quiz.js, ...}
    sims/{chemdraw.js, makesim.js, ...}
    snippets/{legend_fold.html, feynman_fold.html}
    data/{components.json, glossary.json, elements.json, sims.json, messages.json}
  lessons/module_1/
    module.json                  # единый: meta + order + уроки
    u1/{lesson.md, body.html, answers.md}
    u2/… u3/… final/…
dist/                            # выход: module_1.html, module_1.message.txt, styleguide.html
modules/legacy/                  # архив старых монолитов, только чтение
```

### 2.1. Слои

1. **Человек:** `lesson.md` — свободный черновик (билдер не читает).
2. **Агент:** скилл + `components.json` + DESIGN + SIMULATIONS → `body.html` (канон,
   JSON-островки данных) + `answers.md`.
3. **Сборка:** `build.py` читает `course.json`/`module.json`/`body.html` → `dist`.
4. **Ворота:** `lint.py` проверяет канон и данные.
5. **Справка:** `glossary.json`, `elements.json`, `sims.json`, `messages.json`.

### 2.2. Конвейер сборки

`lesson.md` → (агент) → `body.html` → `build.py` → `dist/module_1.html` +
`module_1.message.txt` → отчёт (консоль/Telegram). `lint.py` — перед «готово».

### 2.3. Автоподбор css/js

Билдер сканирует `body.html` на предмет блоков из `components.json` и собирает
уникальный список CSS/JS по карте «блок → ресурсы». Ручные списки в манифесте
упраздняются. Правило: если блок требует JS — его нет в реестре без `produces.js`.

## 3. Модель данных

### 3.1. `course.json`

```json
{
  "title": "Единый курс химии",
  "year": 2026,
  "levels": [
    {
      "id": "A", "title": "Фундамент",
      "modules": [
        {
          "id": "module_1",
          "title": "Химия как наука",
          "themes": ["Что изучает химия", "Тела и вещества", "Методы познания", "Безопасность"],
          "skills": ["различать тело и вещество", "работать в лаборатории безопасно"],
          "prereq": [],
          "lessons_count": 4,
          "time": "~1,5 часа",
          "status": "draft",
          "icon": "🧪"
        }
      ]
    }
  ]
}
```

`status`: `draft` → `lessons_done` → `lint_ok` → `ready`. Статус повышает билдер по факту.

### 3.2. `module.json` (единый, на модуль)

```json
{
  "id": "module_1",
  "title": "Модуль 1. Химия как наука",
  "badge": "Модуль 1 · Химия как наука · ~1 час",
  "digest": "…1–2 предложения…",
  "questions": ["Из чего состоит всё вокруг?", "…"],
  "order": ["u1", "u2", "u3", "final"],
  "lessons": [
    {
      "file": "u1",
      "title": "Урок 1. Как учимся и что изучает химия",
      "chip": "Урок 1",
      "pill": "1",
      "time": "~20 минут",
      "questions": ["Что изучает химия?", "…"],
      "canon": "1.0"
    }
  ]
}
```

`canon` — версия канона, которой собран урок (для пометки устаревших).

### 3.3. `components.json` (реестр блоков, фрагмент)

```json
{
  "version": "1.0",
  "components": [
    {
      "id": "callout",
      "purpose": "Смысловой блок: идея/предупреждение/заметка/вывод",
      "classes": ["callout", "callout-idea", "callout-warn", "callout-note", "callout-ok"],
      "required_attrs": ["data-variant"],
      "allowed_variants": ["idea", "warn", "note", "ok"],
      "children": "text/inline",
      "produces": { "css": "core", "js": [] },
      "example": "<div class=\"callout callout-warn\" data-variant=\"warn\">…</div>"
    },
    {
      "id": "quiz",
      "purpose": "Тест/микровопрос",
      "classes": ["test-question", "test-options", "test-option", "explanation"],
      "required_attrs": ["data-config", "data-quiz-id"],
      "children": "none (данные в JSON-островке)",
      "produces": { "css": "core", "js": ["quiz"] },
      "example": "<div id=\"quiz-u1-entry\" data-config=\"entry\"></div>"
    }
  ]
}
```

Таблицу блока из DESIGN §3 можно генерировать из этого файла (единый источник).

### 3.4. `glossary.json`

```json
{ "термин": { "definition": "определение в одну строку", "module": "module_1" } }
```

Автоподсветка: термин в тексте помечается `<span class="term" data-term="термин">`;
клик открывает небольшое окно с определением (данные из JSON-островка `#glossary`).

### 3.5. `messages.json`

```json
{
  "entryFail": ["Не страшно — сейчас всё узнаешь. Повтори предыдущий урок и пройди входной снова."],
  "finalPass": ["🎉 Модуль пройден!"],
  "finalFail": ["Есть над чем поработать. Вернись к текущему уроку и попробуй ещё раз."],
  "warmupDone": ["Разминка пройдена."],
  "practiceDone": ["Хорошо! Двигаемся дальше."]
}
```

### 3.6. `sims.json`

```json
{ "state_of_matter": { "title": "Агрегатные состояния", "type": "tune",
  "used_in": ["module_2/u1"], "status": "draft" } }
```

## 4. Компоненты и канон

### 4.1. Канонические блоки урока (порядок)
`hero → легенда → Фейнман-напоминание → разогрев/вход → теория(+симы) →
реальная задача → интерактив → практикум → Фейнман → задачка★ → выжимка →
домашка → итог → оглавление`.

### 4.2. Формулы (компоненты)
| Компонент | Класс | Назначение |
|---|---|---|
| Формула | `.formula` + `<sub>/<sup>` | `H₂O`, `Ca²⁺` |
| Уравнение | `.formula-block` | центрированное, со стрелкой |
| Стрелка | `.reaction-arrow` | `→`/`⇌` + условия над/под |
| Состояние | `.state-tag` | `(г)/(ж)/(тв)/(р-р)` |
| Степень окисления | `.ox-state` | бейдж; только с Модуля 13 |
| Атом-чип | `.atom-chip` | цвет CPK из `elements.json` |

Правила: формулы не набирать вручную; индексы/заряды только `<sub>/<sup>`;
уравнение — всегда блок; `aria-label` с проговариванием.

### 4.3. Симы
- Ядро `ChemDraw`: `drawAtom/drawBond/drawLattice/drawCharge/drawMolecule/drawReactionSwarm`.
- Обёртка `makeSim(opts)`: заголовок → cta → тело → транспорт → статус → мета → микровопрос.
- LOD: макро (SVG/DOM) ↔ микро (canvas), переключатель с плавным zoom.
- Производительность: DPR-скейл + rAF-менеджер с паузой по `IntersectionObserver`.

## 5. Билдер, линт, движок

### 5.1. `build.py`
- Читает `course.json`, `module.json`, `body.html`, JSON-островки.
- Сам определяет css/js по блокам.
- Собирает поурочно (для точечной правки) и модуль целиком (`dist/module_1.html`).
- Пишет `.message.txt`, отчёт; флаг `--send` → Telegram из `.env`.
- Подкоманда `new module_N` — скаффолд папки модуля.
- Выносит `shell.html` как шаблон (не хардкод в Python).
- Прописывает в урок пометку версии канона.

### 5.2. `lint.py` (ERROR/WARN)
**ERROR:** JS-синтаксис (`node --check`); баланс `<div>/<section>`; наличие `id`,
которых ищет JS; валидность JSON-островков тестов (2+ варианта, ровно один верный,
непустой `why`); все CSS-классы из реестра; инлайн-`style` запрещён; пустые блоки.
**WARN:** размер файла > 1.5 МБ; неизвестный тип интерактива.

### 5.3. `quiz.js`
Один движок, читает `#quiz-<id>` JSON-островок. Конфиг: `type` (warmup/entry/practice/
final/safety), `threshold` (по умолчанию 80%), `shuffle`, `bank`.
Типы вопросов: `single`, `multi`, `match`.
Цикл: рендер → клик → блокировка вопроса → подсветка `correct/wrong` → объяснение →
счёт → итог (случайный текст из `messages.json`) → разбор ошибок. Ретрай всегда.

## 6. Пилот: миграция Модуля 1

1. `module.json` единый (слить `manifest.json` + `module.json`).
2. Каждый урок: `lesson.md` (черновик) + `body.html` (канон) + `answers.md`.
3. Тесты → JSON-островки + `quiz.js`.
4. Убрать prev/next навигацию, добавить оглавление + sticky.
5. Весь контент — только канонические классы, без инлайн-стилей.
6. `lint.py` зелёный; `build.py module_1 --send` отдаёт файл.
7. Автор проверяет `dist/module_1.html` на телефоне.

После подтверждения: удалить ручные `modules/mod01/*.html`, зафиксировать тег.

## 8. Риски и митигации

| Риск | Митигация |
|---|---|
| Агент выдаёт неканонический контент | реестр + `lint.py` + скилл + витрина |
| Расход токенов | точечная правка одного урока, скиллы, JSON-данные |
| Потеря работы | GitHub, `dist` коммитим, тег перед рефактором |
| Дрейф документации | доки правятся тем же коммитом; реестр — машинный источник |
| Дрейф от канона | `lint.py` ERROR блокирует «готово» |
| Тяжёлые симы на телефоне | DPR, пауза rAF, деградация в стоп-кадр |
| Раздувание файла | мягкий WARN по размеру; при тормозах — пилим модуль |
