# AGENTS.md — карта проекта для агента

Курс интерактивной химии: Markdown-источник урока (`lesson.md`) + JSON-данные → автономные офлайн-HTML.
Полный контекст — `README.md`. Здесь — **что где лежит и какой скилл когда звать**.

## Skills

Проектные скиллы лежат в `.opencode/skills/`. Порядок вызовов:

| Задача | Скилл |
|---|---|
| Спланировать/написать/переписать урок из `lesson.md` | `chemistry-lesson` (мастер) |
| Тесты, квизы, drop-игры, сценарии, таймлайны, оборудование | `chemistry-interactive` |
| Проверка педагогического качества готового урока | `chemistry-review` |
| Симуляции | `chemistry-sim` (пишется после P2: `makeSim`/`ChemDraw`) |
| Отдать внешнему (free) агенту контракт на генерацию урока | `chemistry-lesson-canon` |

`chemistry-lesson` **вызывает** `chemistry-interactive` для тестов/игр и
`chemistry-sim` для симуляций; в конце может позвать `chemistry-review`.

`chemistry-lesson-canon` — **самодостаточный скилл-контракт** (вендринг канона:
каркас, классы, quiz, `module.json`). Его отдают внешнему агенту вместе с готовым
примером урока; тот возвращает `body.html` + фрагмент `module.json`, которые здесь
прогоняются `lint`/`build`. Каталог классов — генерируемый:
`python3 src/export_skill_catalog.py` (источник — `src/shared/data/components.json`).

## Где что лежит

| Что | Путь |
|---|---|
| Структура курса (уровни, модули, статусы) | `course.json` |
| Мета и порядок уроков модуля | `src/lessons/module_N/module.json` |
| Урок: источник / канон / ответы | `src/lessons/module_N/uN/{lesson.md, body.html, answers.md}` |
| Канон блоков и CSS-классов | `src/shared/data/components.json` |
| Дизайн-система (принципы, каркас, quiz, симы) | `DESIGN.md` |
| Визуальные сущности (CPK, LOD, отрисовка) | `SIMULATIONS.md` |
| Термины / элементы / тексты результатов / реестр симов | `src/shared/data/{glossary,elements,messages,sims}.json` |
| Оболочка HTML | `src/shared/shell.html` |
| Движки | `src/shared/js/` |
| Собранные файлы (коммитятся, **агенту не читать**) | `dist/` |
| Старые монолиты (только чтение, **агенту не читать**) | `modules/legacy/` |

## Команды

```bash
python3 src/build.py module_1        # собрать модуль
python3 src/lint.py module_1         # ворота «готово» (ERROR/WARN)
python3 src/build.py module_1 --send # собрать и отправить в Telegram
```

**Перед сдачей урока обязательно:** `python3 src/lint.py <module>` → `LINT OK`, затем
`python3 src/build.py <module>` → все уроки `OK`.

## Экономия токенов: что читать (Repowise)

- **Артефакты не читать.** `dist/**/*.html` и `modules/legacy/*.html` —
  сгенерированные/read-only монолиты (130–190 KB, ~35–50k токенов за файл).
  Нужен результат сборки — запусти `python3 src/build.py <module>` и смотри вывод,
  а не открывай `dist`.
- **Источник, а не продукт.** Правки — в `lesson.md`; канон
  `src/lessons/**/body.html` читать точечно. Один урок: `body.html` ~4× тяжелее
  своего `lesson.md`.
- **Вопрос, а не файл.** Прежде чем `read` — спроси точечно через repowise MCP:
  `search_codebase`, `get_context`, `get_answer` (0.4–5k токенов вместо ~47k).
  Скелет (`get_context include:["skeleton"]`) — для исходников, не для HTML.
- **Селектор, а не документ.** Нужен кусок HTML — выдерни адресно (`grep` по
  `id=`/`class=`), не читай файл целиком.
- **Шумные команды — через `repowise distill`.** `python3 src/lint.py`,
  `python3 src/build.py`, `git status/diff/log`, `ls`, `grep` прогоняй как
  `repowise distill <cmd>`; полный вывод достаётся `repowise expand <ref>`.
- `dist/` и `modules/legacy/` внесены в `.repowiseIgnore` — из индекса исключены,
  не удивляйся, что их нет в поиске.

## Жёсткие правила

- Классы — **только** из `src/shared/data/components.json`. Нет класса — не выдумывать,
  а добавить компонент в реестр (или использовать утилиту).
- **Инлайн-`style` в контенте запрещён** (`lint` ловит).
- **Границы глубины:** у каждого модуля в `course.json` есть `not_yet` (термины и детали,
  которые нельзя вводить раньше времени), у главы — `depth` (лестница глубины). Авторя
  урок, не забегать вперёд: подробность — только в своём модуле. Соблюдение ведёт
  `chemistry-lesson`.
- `lesson.md` — **источник истины**: его правит человек/агент, инструменты его
  **не перезаписывают** (при расхождении md и канона — побеждает md). Билдер читает
  только `body.html` + `module.json`; компилирует md→канон агент по скиллу
  `chemistry-lesson`. `src/lesson_md.py` — **export-only** (`--missing` по умолчанию,
  `--force`, `--check`), не запускать поверх отредактированного черновика.
- Вводный блок «О чём этот модуль/урок» (`stage s-intro` + `card-grid` + `callout-idea`) —
  из `module.json` (`intro` модуля и каждого урока), рендерит билдер; в `body.html` не хардкодить.
  Модульный — на `entry` (или первом уроке), урочный — на каждом `uN`. QA-карточек (`qa-card`) нет.
- **Практикум** (`stage s-prac`, поле `practical`) и **ДЗ** (`stage s-hw`, поле `homework`) —
  тоже из `module.json` на каждом `uN`, рендерит билдер; в `body.html` не хардкодить.
  ДЗ: 4 задачи + одна со ★ + 1–2 задания «объясни простыми словами». Отдельного блока
  «Рефлексия по Фейнману» больше нет (его вопросы ушли в ДЗ).
- Тесты — JSON-островок `<script type="application/json" id="quiz-…-data">`, не хардкод в JS.
- Ответы (Фейнман, ★, тесты) — только в `answers.md`, в урок не встраивать.
- Порог тестов 80% везде; без полбалла; повторы неограниченны; блокировки нет.
- Автономность: ноль внешних `<script src>`/`<link>`/CDN; всё инлайнит билдер.
- Главный сценарий — вертикальный телефон; тап ≥44px; hover дублируется тапом.
- `dist/` коммитится; версии — одна ветка `main` + теги на готовые модули.
- `.env` (токен бота), `.repowise/`, `.mcp.json`, `.claude/`, `.vscode/` — не коммитить.
