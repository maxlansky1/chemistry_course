# Chemistry Lesson Authoring

## Overview

Master skill of the chemistry course content pipeline. It turns a free-form
`lesson.md` draft into a canonical `body.html` (built only from components in
`src/shared/data/components.json`) plus an `answers.md` for the teacher, following
the lesson skeleton in `DESIGN.md` §2. It **orchestrates** the sub-skills
`chemistry-interactive` (quizzes/games) and `chemistry-sim` (simulations).

The mechanical canon (allowed classes, no inline styles, tag balance, quiz JSON
validity, JS syntax) is enforced by `python3 src/lint.py` — this skill is about
**judgment**: structure, tone, objectives, real-life task, Feynman quality.

## When to Use

Use when:
- the author asks to plan, write, or rewrite a lesson from `lesson.md`;
- a lesson must be turned into or migrated to canonical `body.html`;
- adding/updating Feynman prompts, recap, homework, the real-life task;
- applying the teacher's feedback to a lesson.

Do NOT use when:
- only a quiz/game needs work → `chemistry-interactive`;
- only a simulation needs work → `chemistry-sim`;
- only reviewing an existing lesson → `chemistry-review`;
- only the course/module structure changes → edit `course.json`/`module.json` directly.

## Required Context (read before writing)

1. `src/lessons/module_N/uN/lesson.md` — the author's draft (source of intent).
2. `src/lessons/module_N/module.json` — order, lesson title, QA questions, time.
3. `course.json` — theme, skills, prerequisites for this module.
4. `src/shared/data/components.json` — the ONLY allowed blocks and classes.
5. `DESIGN.md` §2 (skeleton), §4 (quizzes), §6 (simulations); `SIMULATIONS.md`.
6. `src/shared/data/glossary.json` — existing terms.
7. Existing `body.html` (when rewriting).

## Lesson Skeleton (order, from DESIGN.md §2)

`hero` (badge, title, QA placeholders `<!--QA-->`) → `${legend_fold}` and
`${feynman_fold}` are injected by the builder **only at module start** → welcome/entry
(if applicable) → theory (+ simulations) → **real-life task** → interactive →
practice → Feynman → starred task (`.thinker`) → recap (`.recap-card`) → homework
(`.homework`, min 5 tasks, last one starred) → final test (final lesson only) →
module table of contents (generated by the builder, not authored).

The builder owns `<div class="container">` and the closing tags — do **not** wrap the
body in a container, and keep `<div>`/`<section>` balanced.

## Workflow

1. **Plan** the lesson — see `references/planning.md`. Write 2–4 learning
   objectives; map the draft onto the skeleton; decide what is prose, what is
   interactive, what is practice. Confirm timing (~15–20 min reading).
2. **Write the prose** — see `references/prose.md` and `references/blocks.md`.
   Neutral narrator, two-layer examples, no answers in the file.
3. **Formulas and terms** — see `references/formulas.md` and `references/glossary.md`.
4. **Delegate interactives**: for each quiz/game/scenario/map block, invoke
   `chemistry-interactive`. Do not hand-write quiz JS.
5. **Delegate simulations**: for each `watch/tune/sandbox` block, invoke
   `chemistry-sim`. If `makeSim`/`ChemDraw` do not exist yet, leave a marked
   `.sim` placeholder and note it — do not fake a simulation.
6. **Close the lesson**: real-life task, Feynman prompts, starred task, recap,
   homework, notebook memo.
7. **Write `answers.md`** — answers to QA, tests, Feynman and the starred task.
   Never put these in `body.html`.
8. **Verify**: `python3 src/lint.py <module>` must print `LINT OK`, then
   `python3 src/build.py <module>` must print `OK` for every lesson. Fix and repeat.
9. Optionally invoke `chemistry-review` for pedagogical QA and apply the remarks.

## Delegation Rules

- Tests/quizzes/games/scenarios/maps → `chemistry-interactive`. Pass the intended
  config and the topic; receive ready markup + JSON islands.
- Simulations → `chemistry-sim`. One simulation = one phenomenon.
- Review → `chemistry-review` (it reports remarks, it does not edit).

## Reference Files

- `references/planning.md` — objectives, block plan, timing, prerequisites.
- `references/prose.md` — tone, two-layer examples, age fit, Feynman.
- `references/blocks.md` — meaning → canonical component map.
- `references/formulas.md` — formulas, equations, reaction conditions.
- `references/glossary.md` — term handling and `.term` markup.

## Common Mistakes

| Mistake | Consequence | Fix |
|---|---|---|
| Inventing a class or inline `style` | `lint` ERROR | Use `components.json`; add a component if truly missing |
| Putting answers in `body.html` | Spoils the lesson | Move to `answers.md` |
| Quiz JS hardcoded in the lesson | Duplicated engine | Use `chemistry-interactive` + JSON island |
| Wrapping body in `.container` | Double container | Builder owns the container |
| Faking a simulation | Dishonest model | Delegate or leave an honest placeholder |
| Skipping `lint`/`build` | Broken delivery | Always run both before done |

## Definition of Done

- `body.html` uses only registry classes, no inline styles, balanced tags.
- All skeleton blocks present and ordered (optional blocks may be omitted).
- Each topic is tied to a real-life task; Feynman prompts are open.
- Interactives delegated; quizzes validated; answers live in `answers.md`.
- `python3 src/lint.py <module>` → `LINT OK`; `python3 src/build.py <module>` → all `OK`.
