# Интерактивный курс химии

Авторский курс химии — не по классам, а как **единый последовательный учебник**.
Каждый модуль — это автономный интерактивный HTML-файл: теория, наглядные
симуляции, практика, рукописная домашка и самопроверка в одном документе. Ученик
открывает файл на телефоне из Telegram (или встраивает в доску tldraw) и проходит
шаг за шагом.

Репозиторий — это **движок + контент-пайплайн**: Markdown-источник (`lesson.md`) и JSON-данные
превращаются билдером в автономные офлайн-HTML без единой внешней зависимости.

---

## 1. Концепция курса

Курс строится на принципах **mastery-based learning** — обучение на основе
освоения, а не по расписанию.

**Ключевые идеи:**

1. **Единый путь, а не «класс».** Не курс для 7/8/9 класса, а один учебник, который
   ученик открывает с любой точки и осваивает последовательно.
2. **Линейность.** Каждый модуль опирается только на предыдущие; пререквизиты
   явно прописаны в `course.json`.
3. **Вход с любой точки.** Ученик проверяется входным тестом по пререквизитам
   и начинает с нужного модуля.
4. **Мастерство как пропуск.** Нельзя перейти дальше без 80% на итоговом тесте.
5. **Джонстон — с Главы 2.** До этого треугольник «макро / субмикро / символы»
   не упоминается: Глава 0 идёт на макроуровне, Глава 1 впервые касается частиц
   без формул. С Главы 2 треугольник — рабочий инструмент.
6. **Метод Фейнмана.** После темы ученик объясняет её простыми словами и записывает
   в тетрадь. Проверяет учитель. Сохранения текста в HTML нет.
7. **Тон один, примеры в два слоя.** Нейтральный рассказчик («давай разберёмся»),
   примеры парами: бытовой (кухня, дом) + прикладной (медицина, производство).
8. **Научпоп для любого возраста.** Уровень — как у Перельмана и Фейнмана:
   понятно школьнику, не «по-детски» взрослому.
9. **Реальная задача в каждом уроке.** Тема привязана к практической задаче,
   которую решает химия.
10. **Только рукописная практика.** Тесты — для самопроверки; умение работать
    в тетради развивается отдельно и проверяется учителем лично.
11. **Своевременность и потолок глубины.** Понятие вводится на минимально нужном
    уровне; у каждой главы — **лестница глубины** (макро / качественно /
    количественно), у каждого модуля — **`not_yet`** (что вводить раньше времени
    нельзя). Соблюдение ведёт скилл `chemistry-lesson`.

**Форматы оценивания:** порог 80% везде; без полбалла и «второй попытки»; повторы
неограниченны; блокировки контента нет (ответственность ученика). Результат —
«прошёл / не прошёл», подтверждается скриншотом учителю.

**Технические принципы:** автономный офлайн-файл, весь CSS/JS инлайн, ноль внешних
библиотек; главный сценарий — **вертикальный телефон** 390×844; тап-зоны ≥44px,
hover дублируется тапом; мобильный-first.

## 2. Как это работает у ученика

1. Автор собирает модуль: `python3 src/build.py module_1 --send`.
2. Готовый `dist/module_1.html` приходит в Telegram (или передаётся вручную).
3. Ученик открывает файл на телефоне — офлайн, в любом браузере.
4. Внутри: оглавление → урок 1 (теория + симы + практикум) → домашка в тетрадь →
   урок 2 → … → итоговый тест. Всё в одном файле, со ссылками-якорями.
5. На занятии автор может встроить файл в доску **tldraw** через `iframe`.
6. Результат итогового теста ученик показывает (скриншот).

## 3. Архитектура

Четыре слоя, разделённые по ответственности:

| Слой | Что | Инструмент |
|---|---|---|
| **Человек** | **Источник урока** — правит автор (и агент) | `lesson.md` |
| **Агент** | Компилирует `lesson.md` в канонический HTML + данные + ответы | ИИ-агент + скиллы + `components.json` |
| **Сборка** | `body.html` + `module.json` → автономный HTML, отчёт, Telegram | `src/build.py` |
| **Ворота** | Проверка канона, данных, тегов, id | `src/lint.py` |

```
lesson.md  ──(агент, скилл chemistry-lesson)──▶  body.html + module.json + answers.md
                                                          │
                                                    src/build.py  ──▶  dist/module_N.html
                                                          │                  │
                                                    src/lint.py          Telegram
                                                          │
                                                 course.json / shared/data/*.json
```

**Ключевое правило:** `lesson.md` — **источник истины**; его правит человек/агент и
**никогда не перезаписывают** инструменты. Билдер `lesson.md` не читает: агент
компилирует черновик в канон (`body.html` + `module.json` + `answers.md`), опираясь
на реестр компонентов и дизайн-доки. `src/lesson_md.py` — только **экспорт** канона в md
(по умолчанию не перезаписывает; флаги `--missing`/`--force`/`--check`, можно указать модуль).

Альтернативный путь: **внешний агент** может сразу выдать канонический `body.html` +
фрагмент `module.json` по скиллу-контракту `chemistry-lesson-canon`; тогда здесь остаётся
прогнать `lint.py` + `build.py` и экспортировать `lesson.md`.

## 5. Данные (машинный канон)

| Файл | Назначение |
|---|---|
| `course.json` | 14 глав (`levels`: `0`…`12` + `Ф`) и 40 модулей: `id`, `title`, `themes[]`, `skills[]`, `prereq[]`, `lessons_count`, `time`, `status`, `icon`; у главы — `depth` (лестница глубины), у модуля — `not_yet` (что вводить раньше времени нельзя). Синхронизируется с `PROGRAM.md`. |
| `src/lessons/module_N/module.json` | Мета модуля: `title`, `badge`, `digest`, `intro` (вводный блок «О чём этот модуль»: `subtitle`/`lead`/`cards[]`/`callout`), `order[]`, `lessons[]` (title/chip/pill/time + `css`/`js`, а для каждого `uN` — `intro` (блок «О чём этот урок»), `practical` (описание опыта) и `homework` (4 задачи + ★ + 1–2 «объясни простыми словами»)). Билдер рендерит блоки: модульный `intro` — на `entry` (или первом уроке), урочный `intro`/`practical`/`homework` — на каждом `uN`. |
| `src/shared/data/components.json` | **Реестр канонических блоков**: id, назначение, классы, обязательные атрибуты, что подключает (`produces.css/js`), пример. Его читают билдер и линт. |
| `src/shared/data/glossary.json` | Термин → определение. Питает автоподсветку `.term` (клик → окно). |
| `src/shared/data/elements.json` | CPK-цвета и ковалентные радиусы. Задел под ядро `ChemDraw`. |
| `src/shared/data/messages.json` | Банк текстов результатов теста (случайный выбор по ситуации). |
| `src/shared/data/sims.json` | Реестр симуляций: id, тема, тип, где используется, статус. |

`status` модуля: `draft → lessons_done → lint_ok → ready`.

## 6. Компоненты и канон

Единственный источник разрешённых блоков и CSS-классов —
`src/shared/data/components.json`. Всё, чего нет в реестре, `lint.py` считает
ошибкой. Это защита от «поехавшего стиля».

**Каркас урока (порядок блоков):** hero (бейдж, заголовок) → введение «О чём
модуль/урок» (из `module.json`) → легенда + Фейнман-напоминание (начало модуля) →
разогрев/входной → теория (+ симы) → **реальная задача** → интерактив → практикум
(из `module.json`) → задачка★ → выжимка → домашка (из `module.json`) → итоговый →
оглавление. Единый машинный список блоков — в `components.json`.

**Формулы и химические записи** (компоненты):
- `.formula` — формула, индексы/заряды только `<sub>/<sup>` (`H₂O`, `Ca²⁺`);
- `.formula-block` — уравнение реакции;
- `.reaction-arrow` — стрелка `→`/`⇌` с условиями сверху/снизу;
- `.state-tag` — агрегатное состояние `(г)/(ж)/(тв)/(р-р)`;
- `.ox-state` — степень окисления (вводится с Главы 7);
- `.atom-chip` — инлайн-чип элемента с цветом CPK.

> **Запрет:** инлайн-`style` в контенте. Для раскладки есть утилиты
> (`.mt-14`, `.lead`, `.prose`, `.hero-nav`, …).

## 7. Тестовый движок `quiz.js`

Один движок обслуживает все тесты. Данные — **JSON-островок** в `body.html`:

```html
<div id="quiz-final" data-config="final"></div>
<script type="application/json" id="quiz-final-data">
{ "config": "final", "questions": [ … ] }
</script>
```

**Конфиги:** `warmup` (разминка без порога), `entry` (входной), `practice`
(практикум), `final` (итоговый), `safety` (безопасность). Порог по умолчанию 80%.

**3 типа вопросов:**
- `single` — один правильный: `{"type":"single","q":…,"options":[…],"correct":1,"why":…}`;
- `multi` — несколько: `"correct":[0,2]`;
- `match` — сопоставление: `"left":[…],"right":[…],"correct":[2,0,1]`.

**Механики:** перемешивание; одна попытка на вопрос; обязательное объяснение `why`;
итоговый может быть выборкой из банка; разбор ошибок + кнопка «Пройти заново»;
тексты результатов — из `messages.json`.

## 8. Симуляции (стандарт)

- **Обёртка `makeSim(opts)`** (запланировано): заголовок → подсказка-cta → тело →
  транспорт (▶/⏸/↺/скорость/шаг) → строка состояния → строка-мета «честно/условно»
  → микровопрос.
- **Режимы:** `watch` (смотри), `tune` (крути параметр), `sandbox` (собери сам).
- **Правило честности:** «один сим — одно явление», обязательная строка
  «честно: …; условно: …».
- **LOD-переключатель** «уровень глаз ↔ уровень частиц» (макро SVG/DOM ↔ микро
  canvas) — сквозной механизм.
- **Ядро `ChemDraw`** (запланировано): `drawAtom`/`drawBond`/`drawLattice`/…,
  читает `elements.json`, чтобы все симы рисовали атомы одинаково.
- **Обязательно:** DPR-масштабирование canvas (иначе «мыло» на телефоне) и пауза
  `requestAnimationFrame` вне экрана (`IntersectionObserver`, экономия батареи).
- **Таксономия заданий** (закрытый список): `watch / tune / sandbox / sort / map /
  scenario / quiz / explain`.

## 9. Билдер и линт

### `src/build.py`

- Читает `course.json`, `module.json`, `body.html`, JSON-островки.
- Подбирает CSS/JS по блокам (`detect_assets`; пока для М1 — явные списки в
  `module.json` до полной миграции контента).
- Собирает **поурочно** (`dist/module_1/u1.html`) и **модуль целиком**
  (`dist/module_1.html`).
- Пишет `dist/module_N.message.txt` (пост для Telegram) из того же `module.json`.
- Печатает отчёт по каждому уроку: `OK/FAIL | JS | div | section | missing | KB`.
- Флаг `--send` — отправляет файл и отчёт в Telegram (токен из `.env`).

Команды:
```bash
python3 src/build.py                 # собрать все модули
python3 src/build.py module_1        # только М1
python3 src/build.py module_1 --send # собрать и отправить в Telegram
```

### `src/lint.py` — ворота «готово»

**ERROR** (урок не готов): синтаксис JS (`node --check`); баланс `<div>/<section>`;
наличие `id`, которые ищет JS; валидность JSON-островков тестов; все классы — из
реестра; инлайн-`style` запрещён.
**WARN:** размер файла; неизвестный тип интерактива.

```bash
python3 src/lint.py module_1   # LINT OK / FAIL
```

> `module_1` — эталон, линт зелёный. После ремапа 2.0 собраны `module_2`–`module_5`,
> `module_7`, `module_9` (статус `lint_ok`). `module_6` (уравнения) и `module_8`
> (постоянство состава) ещё не созданы. Отложенный контент — в `modules/parked/`,
> исходники — в `modules/legacy/`.

## 10. Скиллы и процесс

Проект работает в связке с глобальными скиллами агента (opencode) и
проектными документами.

**Глобальные скиллы superpowers** (используются в работе):
- `brainstorming` — превращение идеи в спеку (архитектурный путь);
- `writing-plans` — спека → пошаговый план с проверками;
- `executing-plans` / `subagent-driven-development` — исполнение плана;
- `test-driven-development`, `systematic-debugging`, `verification-before-completion`,
  `requesting-code-review`, `finishing-a-development-branch`;
- `using-git-worktrees`.
- `repowise-auto` — работа с индексом кода (MCP), если `.repowise/` есть.

**Проектные скиллы** (в репозитории, `.opencode/skills/`):
- `chemistry-lesson` — мастер: планирование и написание урока из `lesson.md` в
  канонический `body.html` + `answers.md`. Разделы (`references/`): `planning`,
  `prose`, `blocks`, `formulas`, `glossary`.
- `chemistry-interactive` — тесты/квизы, drop-игры, сценарии, карты/таймлайны,
  оборудование. Разделы: `quiz`, `games`, `scenarios`, `maps`.
- `chemistry-review` — педагогическая приёмка написанного урока (выписывает
  замечания, не правит). Раздел: `checklist`.
- `chemistry-sim` — симуляции (пишется после появления `makeSim`/`ChemDraw`, P2).
- `chemistry-lesson-canon` — самодостаточный **контракт для внешнего агента**: как из
  темы + приложенного примера собрать канонический `body.html` и фрагмент
  `module.json`. Каталог классов генерируется `src/export_skill_catalog.py`.

Порядок вызовов: `chemistry-lesson` вызывает `chemistry-interactive` (и позже
`chemistry-sim`), в конце уместен `chemistry-review`. Карта проекта и правила —
в `AGENTS.md`. Скиллы ссылаются на `components.json` и доки как на источник
правды, а не копируют их.

**Спека и план этого рефакторинга** лежат в `docs/superpowers/` — читать при
погружении в контекст: `specs/…-design.md` и `plans/…-foundation-pilot.md`.

## 11. Соглашения

- **Имена:** только латиница, lowercase, без пробелов: `module_N`, `uN`, `final`,
  `entry`. Кириллица — только внутри контента.
- **Данные отделены от разметки:** вопросы, термины, элементы — в JSON, не в JS.
- **Контент без инлайн-стилей**, только канонические классы из реестра.
- **Офлайн и автономность:** ноль внешних `<script src>`/`<link>`/CDN.
- **Мобильный-first:** вертикальный телефон — основной сценарий.
- **Версионирование:** одна ветка `main`; `dist/` коммитится; теги на готовые
  модули (например `module-1-v1`).
- **Секреты:** `.env` (токен бота) не коммитится. `.repowise/`, `.mcp.json`,
  `.claude/`, `.vscode/` — тоже в `.gitignore`.
